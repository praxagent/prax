# Judge bias audit — 2026-08-20

The second half of [#36](../IDEAS_BACKLOG.md). The first half pinned
`JUDGE_TEMPERATURE` to 0.0 at the four grader sites, which had all been
inheriting `AGENT_TEMPERATURE` (0.7) — the knob tuned to make the *agent* write
well. That fixed a **variance** problem. This measures **bias**, because a judge
can be perfectly reproducible and reproducibly wrong.

Method, thresholds and the surface inventory live in
[`docs/guides/judge-audit.md`](../guides/judge-audit.md); the probes are
[`prax/eval/judge_bias.py`](../../prax/eval/judge_bias.py); the runner is
`scripts/judge_bias_audit.py`. Raw record:
`$PRAX_EVAL_DIR/judge-bias/core-probes.json`.

**Configuration.** 8 goldens (every golden with judged criteria), the **real**
default judge (`eval_judge` routing, `gpt-5.4-nano`, `JUDGE_TEMPERATURE=0.0`),
answers generated by `deepseek-v4-flash` through the forward proxy. `trials=5`,
`orders=3`.

**Roughly 30% of judged criteria return a different verdict when the identical
prompt is graded again at temperature 0.0.** Not a parse failure — every value
was a clean 0.0/1.0, checked per criterion. The task's own hypothesis was right:
pinning temperature is **necessary, not sufficient**. Providers are not
bit-deterministic, and an MoE router can put the same prompt on a different
expert.

## The number that should change how we read every eval

**Judge noise floor on a golden's total: mean 0.217, worst 0.450** (max−min over
five identical re-grades, 0–1 scale).

`proactive_initiative_judgment` scored **0.20, 0.30, 0.45, 0.50 and 0.65 for the
same answer**. `self_regeneration_judgment` ranged 0.45–0.85.

So a golden-score difference **smaller than about 0.2 is indistinguishable from
the judge re-rolling**. That is a hard bound on what the golden suite can resolve,
and it stacks on the sampling interval we already report — the ±16pp Wilson CI on
the n=30 capability suite is *separate* from this. It also lands directly on
[#29](../IDEAS_BACKLOG.md): the self-regen accept-gate is an LLM verdict, and
a gate that flips on a re-roll is not a gate.

This is the same lesson as
[fitness-signal quality is upstream of search quality](autoresearch-beam-search.md),
arriving from a different direction: we knew the signal was *low-resolution*
because n was small. It is also **noisy at fixed n**, and that half was unmeasured
until now.

## Criterion order: 1 in 5 verdicts depends on where the criterion sat

Prax has **no symmetric pairwise judge** — nothing asks "which of these two is
better" — so the classic position-bias probe has no surface. (The near miss:
`eval/runner.py` puts two outputs in one prompt, but their order encodes
*semantics* — one is labelled the known failure — so swapping them changes the
question. That surface is exposed to **anchoring** instead, which is untested and
recorded as open.)

The ordered structure Prax *does* have is the rubric criteria list in one prompt.
Permuting it moved **20% of verdicts on average, up to 40%**. A criterion's
verdict should be a function of the criterion and the answer, never of its
position — and it partly is not.

## Length: it matters, and not in a consistent direction

The mean of +0.050 is the least interesting number here; the **range of −0.450 to
+0.600** is the finding. Adding information-free filler — no entity, number,
citation or claim, with every deterministic `verify` criterion re-checked to
confirm nothing gradeable was added — moved the same substance by up to 0.6 in
*either* direction.

The classic literature finding is that judges reward verbosity. This judge
sometimes does the opposite (`loop_cost_per_accepted_change`: −0.450, i.e. the
padded version of an identical answer lost nearly half the rubric). Both
directions are bias. It is not a *length preference* so much as **sensitivity to
irrelevant text**, which is the more troubling framing because it has no simple
correction.

## `self_preference` was not measured

Reported as **skipped, not clean**. The probe needs a full generator × judge grid
(≥2 families, every judge grading every answer), because one judge disagreeing
with another is *disagreement*, not self-preference — the interaction is the whole
quantity. The grid run was started and abandoned when it became clear the core
probes needed a longer window; it remains open.

This one matters more than it looks: `eval_judge` resolves through the **same tier
ladder as the agent under test**, so on a single-vendor ladder the judge and the
graded agent can be the same model. Prax already implements the mitigation
elsewhere — `agent/spokes/content/reviewer.py` deliberately picks *a different
provider from the writer* — so the discipline exists in this codebase and is
simply not applied where the numbers come from.

## What shipped with this

- **`JUDGE_VOTES`** (default **1** = byte-for-byte previous behaviour). *k*
  independent ballots per judged criterion, strict majority, ties fall to 0. A
  failed or unparseable ballot is **dropped, not counted as a 0** — a crashed call
  is missing evidence, never evidence against the criterion. Chosen over a
  provider `seed` because `seed` is OpenAI-only and best-effort while the live
  ladder runs DeepSeek and GLM through OpenRouter.
- **`note_quality.llm_review` pinned to `JUDGE_TEMPERATURE`.** It returns
  `approved: bool` — a gate — and shipped at a hardcoded 0.2. The same defect the
  eval graders had at 0.7, one layer over with a smaller blast radius. Small is
  not correct. An explicit `temperature` in `llm_routing.yaml` still wins.
- The probe module, the runner, the guide, and **49 key-free tests** across the
  three judge test files (41 of them new).

**Deliberately not done: `JUDGE_VOTES` was not raised.** Raising it re-baselines
every published number, so the flip is a scorer change and belongs behind a
measured A/B, not a belief — the standing rule from
[harness-delta attribution](harness-delta-attribution.md). The instrument to run
that A/B is now in place, which it was not this morning.

## Two things I got wrong, corrected in the instrument

**A null at a saturated baseline is not evidence of absence.** The first real run
returned `+0.000` on all three probes, and it looked like a clean bill of health.
It was not: the answer had scored **0/5 on every criterion**, so the judge was
never near a decision boundary — which is exactly where bias lives. Every probe
now reports baseline saturation and renders a clean result there as **LOW POWER**
rather than "within threshold". Two of the eight goldens above are excluded from
the aggregates for this reason, and the exclusion is *conservative*:
`skill_capture_reuse` sat near the floor and still showed the **largest** drift in
the set.

**`dataclasses.asdict` silently drops computed fields.** The first campaign
finished all eight goldens and then crashed printing its own summary, because
`flagged` is a `@property` and never reached the record. The results survived only
because the runner checkpoints after every golden — which is itself a fix made
earlier the same day, after an all-or-nothing run was killed at 90% and reported
nothing. Serialisation now goes through `ProbeResult.as_record()`.

Both are the same shape as the defect class the
[invariants work](cordis-spatiotemporal-composability.md) named: a function
reporting on a set without a stated invariant about that set.

## Honest limits

n=8 goldens, one judge model, one answer model, five trials each. These are effect
sizes, not rates, and nothing here is a confidence interval. The drift figure is
specific to `gpt-5.4-nano` — the live ladder judges with DeepSeek and GLM, which
are **unmeasured**. The two saturated goldens say more about the cheap answer
model than about the judge. And `self_preference`, the probe most likely to change
what we do, is the one still missing.
