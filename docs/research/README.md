- [Judge robustness on fuzzy tasks (Diffuse AI Control)](diffuse-ai-control-judge-robustness.md) — Reference note on *"Diffuse AI Control on Fuzzy Tasks"* ([arXiv 2606.08892](https://arxiv.org/abs/2606.08892) + Anthropic Alignment companion). **Read for the eval-robustness method, not the AI-control threat model** (an untrusted model deliberately sandbagging isn't Prax's situation). The transferable finding: **weak LLM judges on fuzzy/subjective tasks are systematically gameable by impressive-but-vacuous outputs** (the "totalizing" attack — sweeping claims in borrowed jargon), and a hardened scoring prompt resists it. Directly Prax's case — its golden judge is a LOW-tier (weak) model on irreducibly-judgeable criteria. **Shipped:** (1) `_SCORE_PROMPT` hardened to grade *substance over polish* (score 0 for confident vacuity; reward task-specific specificity; "if you can't point to the span that satisfies it, it isn't satisfied"); (2) a high-tier **supervising auditor** (`score_golden(audit=…)`, `EVAL_AUDITOR_ENABLED`, #26) that re-checks the cheap judge's *passes* and can veto them — maker≠checker on the judge. The complement to `verify` (deterministic where mechanical) + #22 (independent accept signal). Prax takes the static hardening + the stronger-proxy auditor, but **not** the paper's red/blue prompt-*optimization* (needs a ground-truth scorer Prax lacks for fuzzy goldens).

- [CoALA — Cognitive Architectures for Language Agents](coala-cognitive-architectures.md) — Reference note on [arXiv 2309.02427](https://arxiv.org/abs/2309.02427) (Sumers/Yao/Narasimhan/Griffiths, Princeton — the ReAct lineage's own retrospective taxonomy). The field's canonical **"periodic table" for agent design**: three axes — **memory** (working/episodic/semantic/procedural), **actions** (external=grounding vs internal=retrieval/reasoning/learning), **decision cycle** (propose→evaluate→select, then execute) — reframing an LLM as a probabilistic production system and prompting as control flow. **Verdict: document + adopt as a self-audit LENS; don't adopt as architecture** — Prax already instantiates most of CoALA (and its vector+graph semantic memory is *ahead* of the paper's flat assumption), and CoALA has **no safety/trust/governance/eval-gate axis at all** — precisely Prax's thesis, so it validates our *shape* while silent on our *point*. Mapping Prax onto it surfaces two real, generalizable backlog gaps: (1) **memory-writes as first-class governed actions** (CoALA puts *learning* in the same action space as tool calls → a write to Qdrant/Neo4j from untrusted output deserves the same governed-tool audit as an external action); (2) **unlearning / memory-obsolescence** — Prax's two-layer store has no deletion/decay story, which CoALA names as an open problem (pairs with the [learnable-novelty](learnable-novelty.md) consolidation-gate + the [self-improving-survey](self-improving-agents-survey.md) "memory-consolidation is the weakest cell"). Also validates the [self-regen loop](aide2-recursive-self-improvement.md) (#29) as CoALA's "modify your own procedural memory" frontier, and gives a clean four-memory vocabulary spine. Aged well as vocabulary, superseded as structure (LangGraph bakes in the loop).
- [MemGPT — virtual context management](memgpt-virtual-context.md) — Reference note on [arXiv 2310.08560](https://arxiv.org/abs/2310.08560) (Packer/Wooders/Lin/Fang/Patil/Stoica/Gonzalez, UC Berkeley 2023), the canonical **"LLM as operating system"** paper: context window = RAM, everything else = disk, and the *model itself* pages between them. Introduces **main vs external context**, a self-edited **working context** (`core_memory_append`/`replace`), **memory pressure** warnings injected *before* truncation, and recursive-summarisation **eviction** so history is demoted rather than lost. **Verdict: document + adopt ONE mechanism.** Prax reached most of this independently — `memory_remember`/`recall` is archival storage, `conversation_search` is literally the same tool, `progress_service` (6000-char cap, 10-entry window, LLM compaction, detail demoted to `.progress/`) *is* MemGPT's eviction discipline, and the Neo4j entity graph is something MemGPT has no equivalent for. The **one real gap**: `memory_stm_*` exists as storage but is **never injected into the prompt** — the orchestrator reads it in exactly one place, to grep for a timezone string. So Prax can write "the user prefers metric" and never see it again, because an agent does not call `memory_recall` for things it does not know it has forgotten. `agent_plan` is always present but cleared each turn; STM persists but is invisible; MemGPT's working context is **both**. That is a wiring gap, not an architecture gap — storage, tools and injection point all already exist. Weaker second candidate: **memory pressure as a signal** (tell the agent its context is filling *before* truncating), flag-gated and eval-gated since it changes every long turn. **Not** adopted: the OS framing as architecture (a teaching metaphor, not a design constraint), and unbounded self-directed eviction (a model that can silently delete its own history can edit its own audit trail — memory writes stay governed). Honest caveats: 2023 paper, pre-long-context, so its capacity motivation has weakened even though the "know your own memory state" claim has not; abstract + architecture read, **experimental numbers not independently verified** — the recommendation rests on a gap in our code, not on their benchmarks. Concrete version of the "memory consolidation is the weakest cell" finding from [self-improving-survey](self-improving-agents-survey.md), and the mechanism [CoALA](coala-cognitive-architectures.md) describes abstractly.
- [ACM — Agentic Context Management](acm-agentic-context-management.md) — Reference note on [arXiv 2607.23809](https://arxiv.org/abs/2607.23809) (Li/Ming/Chu/Shao/Jin/Xiong): two tools — `manage_context` (LLM-summarise previous turns, **offload the raw messages to storage under an id** — demotion, never deletion) and `query_memory` (retrieve by id, querier-LLM extracts) — with the actual contribution being the POLICY: **the agent decides when to compress** from its own reasoning state, no threshold, no external monitor truncating behind its back. Plus a post-training recipe (Qwen3.5-397B teacher → 9B student, on-policy distillation: inject compression where failed rollouts needed it, strip premature compression from successful ones). Reported (not independently verified): BrowseComp-Plus 0.727 vs 0.570 ReAct, DeepSearchQA 0.425 vs 0.367, SWE-Bench Verified 0.530 vs 0.489, lower peak tokens. **Verdict: adopt the mechanism's shape as the concrete design for the queued MemGPT "memory pressure" row — which it CORRECTS: build two governed tools (`context_compact`/`context_recall`), not a fullness warning injected into the prompt; document-don't-adopt the post-training** (the GPU wall, sixth sighting — by now the strongest standing evidence for the scaffolding-over-weights bet). Their own caveat is load-bearing: weak base models collapse into short trajectories before compression matters, so the mechanism amplifies strength rather than rescuing weakness — pre-register exactly that (first customer for `prax/eval/prereg.py`: kill the flag if compaction doesn't cut peak tokens on long-horizon goldens at unchanged private pass-rate; if it appears to help the CHEAP tier, audit the measurement before believing the miracle). Same no-cross line as MemGPT: offload is additive and auditable, deletion stays governed. Limits: two summarising fetches, tables transcribed not verified, checkpoints not downloaded.

- [ExtractBench — a vendor benchmark, built unusually well](extractbench.md) — Reference note on [LlamaIndex's ExtractBench](https://www.llamaindex.ai/blog/introducing-extractbench): 370 enterprise documents / 4,869 pages / 8 domains / 67 document types each with its own schema, scored on value-level F1 **and per-page cost** across five axes (task challenge, perception, table structure, length, domain). **Verdict: document-don't-adopt** — Prax does not do schema-driven document extraction and should not start — kept for one result that **reshapes a queued decision**. **Caution first: this is a vendor benchmark and the vendor wins it** (LlamaExtract Agentic Plus 95.6% F1, above Codex/GPT-4.5 93.6% and Claude Code/Opus 87.1%). Not an accusation — the construction is genuinely better than most (ground truth from multiple extractors on identical schemas with human review of disagreements; synthetic long lists built data-first *before* PDF rendering; 169 regulatory forms hand-checked with bounding boxes for 84% of fields; dataset and harness public) — but the base rate for "company publishes benchmark, company wins benchmark" is what it is, so treat the **construction** as the contribution and the **ranking** as unverified. **The result that matters to us**: on documents **over 50 pages commercial VLMs drop below 35% recall**, while *"short documents make everyone look good"* (eight systems above 90% under 10 pages). That lands on **#63** (*Prax cannot LOOK at a PDF page*), which proposed rendering pages for a vision model — a naive VLM path would **inherit a severe length cliff exactly where our text layer already fails worst**. It doesn't kill #63, it shrinks it: **render one specific page on demand, never the document**, because "page 14, which came back empty" is a bounded question in the regime VLMs still handle, and the 2026-08-08 coverage banners already name which pages those are, so the two compose. **What does not transfer**: the measured task is schema-driven *field extraction*, not reading comprehension — enough to justify preferring the smaller build, not enough to claim the larger one would fail. **One quiet validation**: grounding ("whether systems identify supporting evidence") is reported as *an open challenge across the field*, and Prax's `_extract_pdf_text` has emitted `--- page N of M ---` markers all along for exactly that reason — cheap, already shipped, apparently not universal.

- [Harness-Delta Attribution — how much of a harness "improvement" is real](harness-delta-attribution.md) — Reference note on [Ding, Lu, Yu, Li, Jin, Liu & Durrett](https://wenwen-d.github.io/blog/harness-delta-attribution/) (Amazon & NYU, 2026-08-06), which is directly about what [#29 self-regeneration](../IDEAS_BACKLOG.md) does: automated optimization of prompts, tools and control flow around a *fixed* executor. Their question — *"a higher aggregate score does not reveal what changed in the system"*. **HDA** decomposes a gain into **overfitting** / **test-time scaling** / **generalizable improvement**, by comparing the baseline against a **compute-matched** variant (`Bcc`) and an overfitting-neutralized one (`Eneutral`). **Verdict: document + ADOPT as #29's accept-gate.** **The numbers quantify our prime directive**: ALFWorld **98% of gains = overfitting**; LiveMath **79%** (a recurring answer pattern *in 21 of 35 training questions*); CREATE **73% test-time scaling**; SWE-bench Verified with Qwen3-4B only **62% residual real**. And the line that should govern the gate — **"in 4 of the 16 settings, the train-selected harness even performs *worse* than the baseline on the held-out set"** — so selecting on training performance doesn't merely fail to help, it actively harms a quarter of the time. Validation-based selection reduced but did not eliminate it, and their overfitting estimate is a self-described **lower bound**. **Two live consequences for us.** (1) It lands on the [skills adopt](amortized-reasoning-skills.md) made three days earlier: compiling a skill from trajectories **is** harness evolution, so the "spike generator" warning recorded there is now a *measured base rate*, and those constraints are the minimum rather than sufficient. (2) **Our campaigns lack the compute-matched control** — the 2026-08-10 model campaign compared luna-pro (~230k tokens/case) against glm-5.2 (63–107k) on pass rate; tokens were reported honestly but not *matched*, so part of any difference could be test-time scaling wearing a model comparison's clothes. The rule to adopt: **never read a pass-rate delta without the token delta beside it**, and make #29's gate held-out, compute-matched and **rejection-biased**. **Honest limits**: a blog post rather than peer-reviewed — though all major claims come from the authors' own controlled experiments with held-out evaluation, which is more than most — figures unverified here, and the base rates may not transfer to a proposer weaker than the Claude Opus they used.
- [DeLM — decentralized agents with a shared verified context](decentralized-shared-context.md) — Reference note on [arXiv 2606.10662](https://arxiv.org/abs/2606.10662) (Mao, Mirhoseini). Caveat: "no universal harness" proven on 3 math tasks / 4 models — strong for discovery search, a hypothesis for general agent tasks. ## LLM behavior & interpretability — why model internals shape the harness

A standing lane for research into **how models actually behave/represent things
internally**, read for its **harness implications**. The premise: the harness is
built *around* a model whose internal dynamics are a **design input**, not a black
box — so findings about belief states, representation geometry, context-order
effects, introspective faithfulness, and failure geometry should inform Prax's
context engineering, reliability guards, and verification design. Prax can't read
activations (it's an API consumer), so these land as **principles + validation**,
realized through output-level proxies — unless a self-hosted backend ([#20](../IDEAS_BACKLOG.md))
later exposes hidden states.

## Key Takeaways

1. **Planning is not optional** — it's the single highest-leverage intervention for multi-step tasks.
2. **Verification beats generation** — checking work is cheaper and more reliable than generating it perfectly the first time.
3. **Persistence prevents drift** — re-inject state every turn; don't trust the context window to remember.
4. **Bound your parallelism** — diminishing returns kick in hard after ~4 concurrent sub-agents.
5. **Make the honest path the smooth path** — architectural enforcement (plan requirements, verification gates) works better than prompt-only instructions.
6. **Fewer tools, better choices** — tool selection accuracy collapses past 20–50 tools. Use hub-and-spoke delegation or on-demand tool search to keep each agent's tool set focused.
7. **Diverse reviewers improve quality** — different models/providers in a review loop outperform same-model self-critique by 9+ percentage points.
8. **Put security boundaries at the OS level** — in-process Python sandboxing is fundamentally fragile (the Glass Sandbox). Use subprocess/process isolation as the primary boundary, keep in-process guards as defence-in-depth, and make the framework enforce limits the plugin code cannot override.
9. **Let the data choose the model** — Thompson Sampling learns which tier works best per component, replacing guesswork with Bayesian inference.
10. **Spend compute where it matters** — difficulty-driven routing allocates expensive models to hard tasks and cheap models to easy ones, matching adaptive computation research.
11. **Never trust the model's self-reported confidence** — LLMs are systematically miscalibrated due to RLHF. Measure uncertainty extrinsically through prediction errors, behavioral variance, and token entropy. The harness must be the arbiter of confidence, not the model.
12. **Prove every mechanism earns its complexity** — log prediction errors, correlate with outcomes, A/B test epistemic gating. Remove mechanisms that don't measurably improve task completion.
13. **Benchmark externally** — internal tests validate architecture; external benchmarks (GAIA, SWE-bench) establish competitive positioning and surface blind spots.
14. **Autonomy is a continuum, not a trichotomy** — the meaningful question isn't "hardcoded vs dynamic" but "which degrees of freedom at runtime". Use an autonomy-level taxonomy: **L0** (recipe selection only), **L1** (parameterized fixed skeleton — prompts/rubric/budget dynamic, shape fixed), **L2** (validated graph composition from typed primitives), **L3** (unbounded — empirically broken, avoid). Pure dynamic composition is empirically fragile (AutoGPT-style); pure hardcoded pipelines can't cover the long tail. The winning shape across Voyager, ChatHTN, LLM-Modulo, RAP, MetaGPT, and Anthropic's orchestrator-workers is: **deterministic backbone + library of proven units + LLM as gap-filler when retrieval misses + hard verifier on output**. Prax today is L0 with L1 machinery built but not exposed. Before escalating, **instrument the current system first** — measure where L0 actually fails (Pareto chart of missing shapes) and justify L1/L2 from evidence, not ideology.
15. **Agentic to-do flows are only conditionally superior** — they beat one-shot prompting on controlled tool-use benchmarks by a few percentage points (ReAct 71%→45%; TPTU sequential 55%→50%), but absolute performance collapses on realistic constraint-heavy planning (WebArena 14%, GAIA 15%, TravelPlanner 0.6%). Plan-visibility is double-edged — exposing the to-do list raises cognitive load and can *reduce* plan quality via miscalibrated trust. Dependency graphs beat linear to-dos by ~15 points. Externalize working memory to files instead of stuffing the context window. Treat tool outputs as a to-do-injection attack surface; every agent-added subtask should trace back to a user goal. Plausible plans mislead users more than ugly correct ones do.
